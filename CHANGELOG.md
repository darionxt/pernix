# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project will follow [Semantic Versioning](https://semver.org/) once released.

## [Unreleased]

### Added

- Pausing a Run (§6.6): `crawler.pause()` holds it without ending it, and `crawler.resume()` picks it up again; both return at once, from a Callback, a component, or another task, and `crawler.paused` tells. The workers stop claiming, and no Request is taken from `start()` or `on_idle()`, though the one being produced still enters the Frontier; the Requests in flight finish, with their Callbacks, and are settled once their Items are processed, those in a batch without waiting for it to fill or time out, so a paused Run holds no Lease once those Items are processed. Lease renewals, Cooldowns, proxy refreshes, stats snapshots, and the Item processing go on. A paused Run is never idle, so it does not end on its own, even with nothing left; a Drain ends it as `drained` and a Force Stop as `forced`. A pause before the Run starts makes it start paused; a repeated call, and a call once stopping or after the Run, does nothing. Pausing and resuming are logged and emitted as the new `SpiderPaused` and `SpiderResumed(paused_for)`, the resumed Run claiming again only once `SpiderResumed` is emitted, and counted in `run.pauses` and `run.paused_seconds`, a pause in progress included.
- The stealth preset: `browser.preset = "stealth"` launches the system's own Google Chrome with a window, and its pages without a viewport of their own, so that they get the window's and the screen's real sizes; `bundled`, the default, launches Chrome for Testing without one. `browser.headless` is unset by default, following the preset, and a `channel` or an `executable_path` in `browser.launch_options` still names another browser. The HTTP Fetcher keeps presenting the bundled build, as curl-cffi has no Profile of the system's Chrome, so a Run tells once, at INFO, that the two present two clients, in place of the warnings about another browser, and `pernix check` names the preset. A browser that is not installed fails with a `ComponentError` naming `patchright install <channel>`, and one with a window without a display with one suggesting `xvfb-run`. With a Proxy Pool, the browser is launched with `--webrtc-ip-handling-policy=disable_non_proxied_udp`, so that WebRTC cannot tell pages the machine's own address around the proxies. The HTTP Fetcher does not follow `Alt-Svc` to HTTP/3, nor send ECH, for the reasons `docs/design.md` §5.4 gives. Network checks of what only a real network shows, HTTP/3, ECH, the headers real servers see, the egress through a proxy, and cancellation, run only with `pytest --network-checks`, on a clean network (`tests/network_checks`).
- Client hints as Chrome sends them after `Accept-CH` (`pernix.fetchers.client_hints`). The response to a top-level navigation or form submission, a redirect included, over a potentially trustworthy origin asks for client hints with `Accept-CH`, read as Chrome reads it, which replace those its origin asked for before; an empty one forgets them, and one that is not a list of tokens changes nothing. With the pinned Profile, the HTTP Fetcher sends them with the navigations, form submissions, and iframes of that origin, and with the other requests its pages make to it, in Chrome's order and with the values the browser's pages present: the high-entropy hints of the User-Agent, the full version, the viewport, the device pixel ratio, the media preferences, the machine's memory as Chrome rounds it, and the network hints of a fast connection, with Chrome's noise for each host. A redirect adds the hints of the origin it leads to and keeps those sent, even to another origin, as Chrome does. A navigation whose `Critical-CH` needs a hint its first request did not send is sent again from the Request's URL, once for each origin, keeping the cookies the response dropped set; that response is not in `Response.history`. `Session.client_hints` keeps the hints of each origin, with its state (`SessionState.client_hints`, `StateDelta.client_hints`, merged by origin, the later save winning); a fetch without a Session keeps them within its redirect chain. The browser keeps in the Session those its pages' navigations ask for, and a context is taught the Session's with a navigation answered in the browser itself, for which Chrome connects to the origin but sends it nothing (`pernix.fetchers.browser_hints`). The Profile contract tests compare the requests after `Accept-CH` and `Critical-CH`, and a Session's cookies of several paths, over HTTP/2 and HTTP/1.1; the order of the hints of a page's requests, and the HPACK of cookie fields shorter than 20 bytes, are known differences.
- A time limit for Callbacks: with `callbacks.timeout` set, off by default, the spider chain, the spider Middleware and the Callback, may take that many seconds in all to produce the outputs of a Response, Inline Fetches and other awaits included, but not the time its outputs wait to be handed on, such as while the Item queue is full. Once the time runs out, the Callback is cancelled at the `await` it is in, and one that ran past it without awaiting is stopped as soon as it gives an output, which is not taken, or ends; it fails with the new `CallbackTimeout`, a `TimeoutError` naming it: as any error of a Callback, it is not retried, its errback gets it, the Request is kept as a Dead Request, and the outputs yielded before are kept; a page it kept is closed, and its slot given back. Each errback gets as long for its own, and one whose time runs out is logged as one that raises. Stats: `callbacks.timeouts` and `callbacks.errback_timeouts`.
- The locale and the time zone of `Intl` in the browser (ADR 0010). Its pages, their frames at any depth, and their dedicated, shared, and service workers present the first language of `locale`, as given, such as `de-DE`, as the locale of `Intl`, and the time zone of a new top-level `timezone` setting, an IANA name such as `Europe/Berlin`, `None` by default for the machine's; both are ordinary settings, set in `Spider.settings` like any other. A name the system's time zone data does not hold, such as `+08:00`, is a `SettingsError`; Windows has the data only with the `tzdata` package. No header changes: the time zone is patchright's `timezone_id`, and the locale Chrome's `Emulation.setLocaleOverride`, set through a DevTools session of each page, which also attaches to its cross-site frames and service workers and sets both before they run (`pernix.fetchers.page_intl`). A page the page opens in another process presents the machine's locale. `BrowserFetcher` takes `timezone`, and the Profile contract tests a time zone too.
- A watchdog of the event loop: once code that never awaits, such as `time.sleep()`, a synchronous HTTP call, or a long parse in a Callback, a Middleware, or a Pipeline, has blocked the event loop, and with it the whole Run, for `loop.block_threshold` seconds (30; 0 turns it off), a daemon thread of the Run logs a WARNING with the stack of the loop's thread, naming the code that blocks it, once per block, and once the loop runs again, an INFO line with how long it was blocked. Stats: `loop.blocks`, and `loop.block_seconds`, their seconds in all. A C call that holds the GIL delays the warning until it returns. `pernix.stats.LoopWatchdog` watches the loop, and `LoopLag(watchdog=...)` beats for it, at least four times per threshold.
- What leaves the machine besides a page's own requests (§5.4). Through an HTTP proxy, with the pinned Profile, the HTTP Fetcher sends the `CONNECT` Chrome sends, with `Proxy-Connection: keep-alive` and the request's `User-Agent` after `Host`, and a request for an `http://` URL with `Proxy-Connection: keep-alive` in the place of `Connection` and `Proxy-Authorization` after it. The requests the browser makes on its own, which belong to no context and so ignore the contexts' proxies, such as the network time, its Google accounts, push messaging's check-in, and component updates, go to a refusing proxy every browser is launched with, so that nothing leaves from the machine's own address: each context gets a proxy of its own, the Request's or its Session's, that of `network.public_only`, which moves from the browser to its contexts, or none, reaching hosts directly. A `proxy` in `browser.launch_options` is taken for the browser's own instead. Contract tests compare both Fetchers' requests at a loopback proxy; in headless mode the browser's `CONNECT` names it `HeadlessChrome`, and Chrome sends credentials to a proxy only once asked, where curl sends Basic ones at once, which tests expected to fail record. `RefusingProxy.refused` keeps the latest targets refused, logged at DEBUG.
- JSON answers of proxy APIs, read without a provider: `proxies.api_json`, a `pernix.proxies.JsonAnswer` table, maps an answer's fields. `list` is the path of the list of proxies, keys joined by dots, a key of digits indexing a list, the answer itself when empty; an entry that is a string is a proxy's address, and one that is an object is read through `address`, or else `host` and `port`, with `username`, `password`, and `scheme` (`http`). `expires` names the field telling when each proxy expires, as `expires_format` says: `timestamp`, `timestamp_ms`, `datetime`, an ISO 8601 date and time with or without an offset, which needs `timezone`, an IANA name or a fixed offset such as `+08:00`, or `seconds`, left once the answer arrived; an entry without it expires as `proxies.api_lifetime` says. An answer that does not match gives no proxy, with a warning naming the path it lacks, never the API's URL, and counts toward `proxies.extract_attempts`, and an entry that cannot be read is skipped, named by its position and field. Time zone names need the system's time zone data, which Windows lacks without the `tzdata` package; a fixed offset needs none, and an unknown name is a `SettingsError` saying so. `proxy_from_parts()` builds a proxy URL from its parts.
- Requests as the browser makes them: with the pinned Profile, the HTTP Fetcher sends the headers Chrome sends for each kind of request, in Chrome's order, with their `Priority` and HTTP/2 stream weight. A GET is a top-level navigation, a POST of a form (`application/x-www-form-urlencoded`, `multipart/form-data`, `text/plain`) a form submission, and any other request, such as a POST of JSON, a `fetch()`; a `Sec-Fetch-Dest` header of `document`, `iframe`, `empty`, `style`, `script`, or `image` names the kind instead (`pernix.request_kinds`). A Request's `Referer` header names the page it comes from, from which the `Referer` sent (`strict-origin-when-cross-origin`), the `Origin`, and `Sec-Fetch-Site` are made, over the whole redirect chain; an empty one names none. A new setting, `http.inherit_referer`, off by default, has a Request constructed in a Callback or a spider Middleware without a `Referer` take the page its Response belongs to: the Response's URL when it is a document, else the `Referer` of its Request. A Request's own headers replace the kind's in place, others going after a navigation's and first among a page's. A `fetch()` to another origin than its page's sends only the Request's own cookies, and keeps none. To an `http://` host other than a loopback one, Chrome's reduced set goes: no client hints, no `Sec-Fetch-*`, and `Accept-Encoding: gzip, deflate`. Over HTTP/1.1, `Connection: keep-alive` follows `Host`. An iframe or a load is a GET, and only a `document` renders, else `ValueError`; with the pinned Profile, a `Sec-Fetch-Dest` pernix makes no request for fails the fetch with `ValueError`. The browser loads a rendered Request as typed in, without its `Referer`. The Profile contract tests compare each kind with what a page makes Chrome send.
- Blocked-response detection: `Spider.is_blocked(response)` tells a Response in which the site refuses its Session, or its proxy, by default one whose status is in `blocked.statuses` (403); override it for challenge pages, such as those served with status 200. 429 stays Rate Limited, and 401 is for `is_logged_out()`. A Response found Blocked raises the new `Blocked`, a `Retry`, instead of reaching its Callback, and is retried at once under the new retry budget `blocked`, up to `retry.blocked` (3) times, which take none of `retry.times`: with a Session Pool, with another Session and its proxy, a new one rather than the Session just Blocked while the pool has room, the Lease being released as `blocked` and the Session Retired after `sessions.max_blocks` (3) in a row, a fetch that went well ending the row; without one, only when the retry can go through another of the Run's proxies, as one is available, or be rendered, a 403 otherwise reaching its Callback as before. With `blocked.render`, an HTTP Request found Blocked is retried rendered, unless it names its Fetcher. A Request naming its Session, or an Inline Fetch continuing one, retries with it, in place for an Inline Fetch; one sharing the Lease of the fetch it is nested in raises `Blocked` to it. Once the budget is spent, the Request fails with `RetriesExhausted`, which its errback gets. The Responses of a login are not judged, and Blocked Responses take no part in proxy health. `Decision.retry(..., request=...)` retries another Request in place of the one tried, keeping the Session and the proxy it was scheduled with, `Frontier.nack(..., request=...)` keeps it, with a conformance test, and `retried_instead()` tells it. Stats: `responses.blocked`, with `sessions.outcomes.blocked`, `sessions.retirements`, and `requests.retried_by_budget.blocked` for the switches.
- The HTTP Fetcher and the browser name the client alike (ADR 0010). With the pinned Profile, HTTP requests send the `sec-ch-ua`, `sec-ch-ua-mobile`, `sec-ch-ua-platform`, `User-Agent`, and `Accept-Language` of the bundled Chrome for Testing 151 build on the platform the Run is on, each in the place of the Profile's own, unless the Request sets its own; other Profiles send theirs. In headless mode, the browser's contexts present its own User-Agent without `HeadlessChrome`. A new top-level `locale` setting, `["en-US", "en"]` by default, a list or a comma-separated string, sets the languages both present: the browser through Chrome's `--accept-lang`, the HTTP Fetcher with the `Accept-Language` Chrome makes of them. A Run warns, once each, about an `http.impersonate` other than the pinned Profile, launch options naming another browser, a browser of another version than the bundled build, and a browser presenting other languages than `locale`, naming the list to set; `pernix check` prints the Profile and marks it and the browser as pinned or not. The Profile contract tests now compare the values of these headers too. `pernix.fetchers.pinned_pair` records the bundled build.
- Page methods: `Render(setup=self.log_in, action=self.after_load)` runs Spider methods, `async def x(self, page)`, on the patchright `Page`: `setup` before it loads, its routes tried after the Fetcher's, and `action` once `wait_for` and the actions are done, before the screenshot. `pernix.browser.PageMethod(method, optional=..., timeout=...)` lets one fail, logged, or limits its time. A method that times out raises `ActionTimeout`, and one that raises otherwise `ActionError`, naming it, with the cause; `Retry` goes through. They run in rendered Inline Fetches too, and persist by name: a method missing on resume fails at once with `SerializationError`.
- Kept pages: with `Render(keep_page=True)`, the Callback gets the open page as `response.page`, and the Run closes it, with its context, once the attempt ends, whether the Callback returned, raised, or was cancelled. It counts toward `browser.max_pages` meanwhile, and the rendered fetches the Callback makes, its subtasks' included, share its slot, so a Callback holding the last page can still render. Under a Session, what the fetch changed is kept, but not what the page changes during the Callback, and the context is not used again. An Inline Fetch, the shell, and a Fetcher called outside `pernix.fetchers.kept_pages.keeping_pages()` cannot keep a page: `ValueError`. A Callback that fails while its kept page crashed, or its browser was lost, fails with `PageCrashed` or `BrowserLost` instead, its own error the cause, and is retried as the fetch would be, an exception to ADR 0006.
- Supplying proxies from extraction APIs, which hand out new short-lived proxies on request. `proxies.supply = "add"` has each load add the proxies the sources give to those listed rather than replace them, so the Sessions keep theirs. A proxy expires once its `expires` passed, as its source tells, or `proxies.api_lifetime` seconds after the API answered, for an answer of one per line, which tells none; an expired proxy has the new health `expired`, so the Sessions bound to it are bound as their policy says, with the new reason `expired` (`never` Retiring them), then it leaves the pool, unless Retired. With `proxies.min_available`, the API and the provider are asked for more proxies while fewer are available, and when a fetch or a Session finds none, one extraction at a time, `proxies.extract_interval` (1 s) apart at least, until they gave `proxies.max_extracted` proxies, or, on demand, `proxies.extract_attempts` (3) extractions in a row gave none; the Run drains for want of proxies only then. `{count}` in `proxies.api` is replaced by how many proxies are wanted, and the URL as fetched is masked; a provider whose `proxies()` takes a `wanted` keyword is told it. `proxy_url()` reads `host:port:user:password` as `user:password@host:port`. `ProxyPool` gains `add()`, `ProxyHealth` `expired`, and `BindingReason` `expired`. Stats: `proxies.extractions`, `proxies.extracted`, `proxies.extraction_failures`, and `proxies.expirations`.
- Browser Generations (`pernix.fetchers.browser_generations`): each browser runs with a patchright driver of its own, and is replaced by a new one once it is `browser.generation_age` (3600 s) old, opened `browser.generation_pages` (1000) pages, or its processes take more than `browser.generation_memory` MiB (0, not measured, by default; measured with psutil, which the `browser` extra now installs); 0 turns each off. The pages in it finish there while the next go to the new one, it closes once they are done, and its contexts kept for Sessions are closed with it. One browser launches at a time, whether first, replacing another, or restarting.
- Browser failures: a page that crashes fails its fetch with the new `PageCrashed`, a `FetchError` the default retry policy retries. A browser that disconnects, whose driver dies, as the error of a fetch or a dead driver process tells, or that stops answering its health probe, every 10 s, is lost: its fetches are cancelled and fail with the new `BrowserLost`, an unanswering driver is killed, and the next fetch starts another browser. The processes of every browser closed are killed, so a driver that died leaves none behind. Stats: `browser.generations`, `browser.replaced`, `browser.replaced_by_reason.<reason>`, `browser.lost`, `browser.lost_by_reason.<reason>`, and `browser.page_crashes`.
- Retry budgets (`pernix.retry_policy.RetryBudget`): `Decision.retry(delay, reason, budget=RetryBudget(name, limit))` counts a retry against a budget of its own instead of as an attempt; once a Request had `limit` retries under it, it fails with `RetriesExhausted`, naming the budget. The Frontier counts them with the Request, `Frontier.nack(budget=name)` and `Lease.spent`, and Inline Fetches count them in place. `RequestRetried.budget` names the budget, and `requests.retried_by_budget.<budget>` counts its retries. The default policy retries `BrowserLost` at once under the `browser_lost` budget, up to `retry.browser_lost` (3) times, which take none of `retry.times`.
- Sessions that follow their proxy, and proxies of their own, for sites that tie an Account to one address. `proxies.rebind` gains `retired`, with which a Session waits for its proxy while it cools down and is bound to another only once it is Retired or no longer listed, and `never`, with which a Session is Retired with its proxy while the Run goes on with the others; `never` while `proxies.refresh` replaces the proxies is warned about. A binding policy returning `binding.current` keeps the Session on its proxy whatever its health: while the proxy cools down, the Session's Lease is released as the new `proxy_cooldown` outcome, or, after a fetch through the proxy failed, as `proxy_failed` with an `until`, so the Session is not leased again until the proxy is available, its Requests waiting without counting an attempt; once the proxy is Retired or no longer listed, the Lease is released as the new `proxy_retired`, Retiring the Session, and the Requests naming it fail with `SessionError`. A policy may return a `Proxy` record to give a Session a proxy of its own, such as an Account's, or a sticky session on a gateway built from the Session's id: it is checked, its password masked in the Run's log, and its health kept, and the pool holds it for that Session alone, out of the turns and the other Sessions' candidates, without `proxies.max_sessions`, and through refreshes; a URL the pool does not list still fails the fetch. `proxies.binding` alone, with no source, gives the Sessions of a Session Pool their proxies, and without a Session Pool is a `SettingsError`. The policy is now asked at every binding, even while no proxy is available, and once more when a fetch through the Session's proxy failed. `ProxyCandidate` gains `until` and `own`; `ProxyPool.candidates(session)` includes the Session's own, and `ProxyPool.bind()` takes a `Proxy` record to hold as one. An outcome's `until` now cools its Session down whatever its kind, and a Lease is released cooling its Session down until the latest of its fetches'. `sessions.retirements` counts the Sessions Retired, whatever the reason, and the gauges `proxies.available`, `proxies.cooldown`, and `proxies.retired` count the Sessions' own proxies in use. A Run drains for want of proxies only once no Session goes through one of its own either.
- Reading pages for agents and scripts with `pernix fetch`. `--extract text` gives the visible text, laid out as a browser's `innerText` lays it out, without scripts, styles, media, and hidden elements; `--extract markdown` the main content as Markdown, the `<main>`, else the only `<article>`, else the body, without navigation, asides, banners, footers, cookie notices, share buttons, menus, and other boilerplate, its headings, paragraphs, lists, block quotes, tables, code blocks with their language, links, and images with alt text kept, URLs made absolute. Both are built on lxml, with no new dependency. `--css SELECTOR` and `--xpath EXPR`, repeatable and kept in order, read the parts they pick instead, as markup, or as text or Markdown with `--extract`; `--links` lists the http and https links, of the page or of those parts, as absolute URLs with their text, each once. `--max-chars N` cuts what is read. With `--fetcher browser`, reading applies to the rendered page.
- `pernix fetch URL...` and `-i FILE` (`-` for stdin) fetch several URLs as one small Run, so retries, per-domain limits, and concurrency apply, and report each with `--json` as one JSON object per line, as it ends, a failure as that URL's `error`. It exits with 0 when every URL got a Response, whatever its status, and 1 when any did not. The JSON objects start with `"schema": 1` and end with `truncated`; selectors give `matches`, and `--links` gives `links`.
- The address guard: with `network.public_only`, the Fetchers refuse hosts whose addresses are not public, private, loopback, link-local, and others not publicly routable, and connect only to the addresses they checked, against DNS rebinding; `network.allow_hosts` names hosts it lets through. The HTTP Fetcher checks each redirect hop before it is sent, its host resolved; a refused hop raises `NetworkBlocked`. Through a proxy, only hosts written as addresses, and loopback names, are checked, but through a `socks4://` or `socks5://` one, for which curl resolves names itself, those are resolved, checked, and pinned too. The browser sends all its traffic, its own background requests included, through a SOCKS5 proxy on 127.0.0.1 that resolves each host and checks it alike (`pernix.fetchers.address_guard_proxy`), with WebRTC kept off UDP, which would go around it: a refused document, redirect, or navigation of the page raises `NetworkBlocked`, worded as the HTTP Fetcher's, while a refused subresource or WebSocket fails in the page, which renders on without it, counted as `browser.requests_refused` and logged; a Request's host written as an address, or a loopback name, is refused before the browser is launched, and `response.ip_address` is the address the proxy connected the document's host to. A rendered Request through a proxy of its own, or of its Session, is refused with `NetworkBlocked`, as the browser would reach hosts through it unchecked, and `browser.launch_options` that would take the browser around the proxy, a `proxy`, `ignore_default_args`, or Chrome switches setting a proxy or what WebRTC does, raise a `SettingsError` when the browser Fetcher is created. Chrome's `net::ERR_SOCKS_*` errors, such as a SOCKS proxy's refusal, raise `ProxyError`.
- Browser capacity: `browser.max_pages` (8) limits the pages the browser Fetcher has open at once, each that of one fetch, which waits for a free one, in the order asked, before it starts the browser or opens its context; `browser.deadline` counts from then. Rendered Requests have that many workers of their own, apart from the `concurrency` workers that take the other Requests, so HTTP Requests never wait for the browser, nor the browser for them; both kinds share their domain's slot, delay, rate, and cooldowns. A Request a download Middleware switches to Render, and a rendered Inline Fetch, wait for a page in the worker they run in. `Frontier.claim(rendered=...)` claims only the Requests that go to the browser Fetcher, or only the others, as the new `pernix.fetchers.is_rendered()` tells, and `Lease.rendered` says which; the `MemoryFrontier` queues them apart. The browser Fetcher counts `browser.pages`, `browser.contexts`, `browser.pages_open`, `browser.contexts_open`, `browser.page_waits`, and `browser.page_wait_seconds` in the Run's stats, and takes `stats=`.
- Render options and declarative page actions (`pernix.browser`): `Request(render=Render(...))` loads the page in the browser, then waits for `wait_for`, a CSS selector, runs `actions` in order, and takes a whole-page screenshot with `screenshot=True`; `render=True` still renders with no options. The actions are `WaitFor(selector, state=)`, `Scroll(times=, delay=)`, `Click(selector)`, `Type(selector, text, delay=)`, `Evaluate(script, isolated=)`, which runs in the page, reaching its globals, unless isolated, and `Screenshot(full_page=)`; each takes a `timeout`, `browser.action_timeout` (10 s) by default, and may be `optional`, so that its failure is logged and the next action runs. A step that takes too long raises the new `ActionTimeout`, a `Timeout` the default retry policy retries, and one that fails otherwise the new `ActionError`, which it does not. `block` keeps the page from loading resource types, such as `image` or `font`, and from registering service workers, which would load them unseen, replacing the new `browser.block` setting, empty by default; misspelled types are refused with a suggestion, and `document` and `websocket` are refused. `Type` types after what the element holds, and its text is left out of its `repr` and of errors. A navigation of the page to a document that does not load, after the page loaded, fails the fetch with the `FetchError` of the browser's error. `capture` keeps the XHR and fetch responses whose URLs match its globs. `response.browser`, a `RenderResult`, holds the document as received, that an action led to if any, the `CapturedResponse`s, the screenshots, and the results of `Evaluate`; it is `None` for Responses that were not rendered. A `Render` persists with the Request, its actions tagged by kind, and takes no part in the Fingerprint, so a download Middleware can upgrade a Request with `request.replace(render=Render(...))`.
- `crawl(browser=...)` answers rendered Requests with a Fetcher such as a `FakeFetcher`, which may also be the `fetcher`, without starting a browser, and `make_response(browser=RenderResult(...))` builds rendered Responses; a Response `make_response()` builds for a rendered Request is the browser Fetcher's, with an empty `response.browser`.
- The browser in the command line: `pernix browser install [--with-deps]` installs the browser engine the browser Fetcher launches, Chrome for Testing, with patchright's installer, without the headless shell. `pernix fetch URL --fetcher browser` renders the page, and `fetch()` in `pernix shell` takes the keywords of `Request`, such as `await fetch(url, render=True)`, or of `replace()` for a Request, with `Request` preloaded. With the browser Fetcher registered, `pernix check` launches the browser once and names it and its version; an engine that is not installed, reported with `pernix browser install`, and a browser that does not start fail the check, while without the `browser` extra the summary only notes it. A configuration error raised while `pernix fetch` fetches, such as a browser engine that is not installed, exits with 2 instead of 1. The `ComponentError` for a missing engine names `pernix browser install`, and one for a `browser.launch_options.executable_path` that does not exist names that path.
- Binding policies for proxies: `proxies.binding` replaces how Sessions are bound to proxies, as `retry.policy` does, with an object whose `async bind(binding)` returns the proxy to bind, or `None` to wait. A `Binding` gives the Session's id, its Account, its proxy and that proxy's health, why it is being bound (`new`, `lease`, `cooldown`, `retired`, or `unlisted`), and the candidates, each a `ProxyCandidate` with its health, tags, the Sessions bound to it, its failures in a row, and its expiry, least recently used first; `binding.open` gives those available with room for the Session. `proxies.max_sessions` limits the Sessions bound to a proxy, so that with 1 no two share one, overlapping Leases and rebinding included: `ProxyPool.bind(session, proxy)` binds only to a proxy available with room, each Lease holding its proxy until it ends (`release()`), so a Session an overlapping Lease bound to another still counts toward it, and a binding whose proxy another Session took first asks the policy again, a few times. The default, `DefaultBindingPolicy`, binds as before, or, with `proxies.rebind = "every_lease"`, to another proxy at each Lease. `proxies.urls` and providers take `Proxy` records, tables in settings, with `tags` and `expires`. A Session no proxy fits waits a second, counted as `proxies.binding_waits` and logged once. A Session the Session Pool Retires is unbound, so it no longer counts toward its proxy's Sessions. `ProxyPool` gains `max_sessions`, `candidates()`, `release()`, and `unbind()`, and `bind()` takes the proxy to bind.
- Proxies (`pernix.proxies`): once a source is set, Requests go through proxies. They come from `proxies.urls`, from `proxies.file`, a text file of one per line (`read_proxies()`), from `proxies.api`, a `Secret` URL answering with one per line, fetched with an HTTP Fetcher of its own, and from `proxies.provider`, a `ProxyProvider` whose `async proxies()` gives them; all are used together, without duplicates, loaded when the Run starts and again every `proxies.refresh` seconds, if set, when those no longer given stop being used. A proxy is a URL with its port, `http` when the scheme is left out (`proxy_url()`), and its key includes its credentials, so sticky sessions on one gateway stay apart. Without a Session Pool, each attempt goes through the available proxy used least recently, and the Request as sent names it; a Session is bound to the available proxy with the fewest Sessions before its first fetch through it, its login's included, keeps it while it is available, over HTTP and rendered, and is bound to another once it is not, the binding saved with its state (`StateDelta.proxy`) and held by the pool, so overlapping Leases of a Session go through one proxy, and settled once per Lease, so the fetches of a Lease go through one proxy too. A Request with a proxy of its own needs none of the pool's. A `ProxyError` cools its proxy down for `proxies.cooldown` (60 s), doubled with each failure in a row, at most `proxies.cooldown_max` (600 s), and Retires it after `proxies.max_failures` (5) in a row; a Response through it ends the row, and the fetches of one outage count once. Requests wait while every proxy cools down, and once none ever can be used the Run drains. Proxy passwords are masked in the Run's log, and stats name no proxy. `MemoryProxyPool` implements the `ProxyPool` protocol. Stats: `proxies.bindings`, `proxies.failures`, `proxies.cooldowns`, `proxies.retirements`, `proxies.refreshes`, `proxies.refresh_failures`, and the gauges `proxies.available`, `proxies.cooldown`, and `proxies.retired`.
- `Request(proxy="")` sends a Request without a proxy, its Session's included, on both Fetchers. Through a proxy, failing to connect raises `ProxyError`, as curl connects to the proxy alone, and the browser Fetcher refuses a SOCKS proxy with credentials, which Chrome cannot use, with a `ValueError`.
- Sessions in the browser: a rendered Request under a Session is loaded in a browser context kept for that Session, which one fetch uses at a time; concurrent fetches of a Session get one each. A context is created with the Session's localStorage and the proxy of the Request or the Session, and replaced when either changes. Before each fetch it is made to hold the Session's cookies, with the Request's own for that fetch only, and after it, whether the page loaded or not, the cookies the page set, changed, or removed, and the localStorage of its origin, are kept in the Session, so a login in the browser carries over to HTTP and the other way round. Cookies keep their SameSite, expiry, host-only flag, Secure, HttpOnly, and path across the round trip, and the jar keeps what the browser does not tell, such as an unspecified SameSite and when a cookie was first set. At most `browser.max_idle_contexts` (8) contexts are kept idle between fetches, and one idle for `browser.context_idle` (300 s) is closed. Logins may render their pages.
- `CookieJar.discard(key)`, which removes a cookie and records the removal, as an expired one does.
- Logins and Accounts. `pernix.Account` holds login credentials: a `username`, a `password`, an `id` (the username unless given), `extra` credentials, and a `max_concurrency` of 1 by default; the password and the `extra` credentials are `Secret`s, masked in the Run's log. Accounts come from `sessions.accounts`, from `sessions.accounts_file`, a JSON Lines or CSV file (`pernix.account.read_accounts()`), and from `Spider.accounts()`, which yields both and is overridden to import Accounts from elsewhere, such as a database. With Accounts, the Session Pool holds one Session per Account, under its id, and no other. `Spider.login(session, account)` logs every Session of the pool in before its first fetch, those without an Account with `account=None`: one fetch at a time logs a Session in, in its place in its slot and under its Lease, which the login's Inline Fetches share, while the fetches that want the Session wait for it. `Spider.is_logged_out(response)`, a 401 by default, judges the Responses fetched under a Session; one logged out raises the new `LoginExpired`, a `Retry` with no delay, and the Session logs in again before its next fetch. A login that raises cools its Session down for `sessions.cooldown`, and after `sessions.login_attempts` (3) failures in a row the Session is Retired; a fetch logged out right after the login it made counts as a failure too. An Inline Fetch that shares the Lease of the fetch it is nested in, such as one a download Middleware makes, raises `LoginExpired` to it instead, so that it is the outer fetch that is retried once the Session logged in again. A stop cancels an import of Accounts that hangs. A Spider that defines `login()` or `accounts()` without a pool is warned about. Stats: `sessions.logins` and `sessions.login_failures`.
- `SessionPool.logged_in(lease)`, `SessionLease.must_log_in`, and the `login_failed` outcome: a pool whose Sessions log in gives a Session that must log in to one Lease at a time, until its holder logged in; `auth_expired` has the Session log in again, and `login_failed` cools it down and counts the failure, unless the Session logged in again since the Lease was given. `MemorySessionPool` takes `logs_in` and `login_attempts`.
- `RunLog.mask()` masks more values once a Run started, and `revealed_secrets()` finds the `Secret`s inside msgspec Structs.
- Session Pools, enabled with `sessions.enabled`: every Request leases a Session from the Run's in-process pool, `pernix.sessions.MemorySessionPool`, and is sent under it, keeping the cookies set during its fetches. Sessions are created as Requests need them, up to `sessions.size` (8), or all at the start with `sessions.eager`, and each takes `sessions.max_concurrency` (1) fetches at once. `Request(session="id")` leases that Session, created on first use, `session=response.session` continues one, a Request a Callback yields leases its own, and an Inline Fetch continues the Session of the fetch it is nested in or of the Request being handled. A 429 cools only its Session down, until its `Retry-After` or for `sessions.cooldown`, at most `sessions.cooldown_max`, while the domain keeps fetching with the others; a 503 still pauses the domain. A Request waits in the Frontier, without counting an attempt, while no Session is free, and fails with the new `SessionError` when none can ever be leased, or when it names a Session without a pool. Rendered Requests lease Sessions too. Stats under `sessions.*`.
- The `SessionPool` protocol (`pernix.sessions`): `acquire(session=, tags=, timeout=)`, `ready_in()`, `renew()`, `release(lease, outcome)`, `load_state()`, and `save_state(lease, delta)`, with `SessionLease`s that carry a token and expire after `sessions.lease_ttl` unless renewed, `Outcome`s (`ok`, `rate_limited`, `blocked`, `auth_expired`, `proxy_failed`, `error`), and `StateDelta`s that merge per cookie by modification time, removals included. A release or a save from an expired or released Lease is rejected.

Neither cookie values nor storage appear in a `repr`.

HTTP/1.1 for cleartext URLs, HTTP/2 connection reuse, decoded bodies without `Content-Encoding` and `Content-Length`, and `ProxyError` for a 407 from a proxy.

### Changed

- A Request is acknowledged once its Items are processed, rather than once they are queued, so that delivery is at-least-once with every Frontier (ADR 0003): stored, dropped, or failed and passed through the failure Pipelines, and with `stream_items()` once the consumer asks for the next Item. A Request retried with `Retry` after yielding Items is returned only then too, its delay running from then, and a failed one is kept as a Dead Request only once the Items of its errback are processed as well. Meanwhile its worker goes on to the next Request, and its Lease is renewed; the Item queue bounds the Requests waiting so, which count in `frontier.leased`. A Force Stop returns them to the Frontier without counting an attempt, as the Requests in flight. `on_idle()` runs once every Item is processed, and a batch Pipeline processes its batch without waiting for it to fill or time out once nothing else can happen until its Requests are settled, as at the end of a Run, in a Drain, or in a Pause. The Engine takes `put_item(item, ctx, pending)`, counting each Item in the `pernix.items.PendingItems` of its attempt, and `flush_items`; `ItemProcessor` gains `flush()`, and its outlet takes the Item with the function to call once done with it.
- The browser's `Intl` follows `locale`, the default `["en-US", "en"]` included, where it followed the machine, the system on macOS and the environment on Linux: on a machine set to another language, pages now present `en-US` as the locale of `Intl` unless `locale` names another first language.
- `LoopLag.start()` and `stop()` replace `LoopLag.run()`: `start()` starts the sampling task and its watchdog at once, so that code blocking the event loop before the task first runs, such as a `SpiderOpened` subscriber, is watched too.
- With the pinned Profile, the HTTP Fetcher sends the whole header list itself, in Chrome's order for the Request's kind, instead of curl's: a Request's headers of one name go together, and its `Referer`, `Origin`, and `Sec-Fetch-Dest` are made from the page and the kind rather than sent as they are. `blocked.render` retries only navigations and form submissions rendered.
- A string from the environment or the command line for a setting whose type also takes a string, such as `locale`, stays a string when it is not JSON.
- `pernix fetch` fetches as a Run of its own, retrying as the retry policy says, even for one URL; `-s retry.times=0` makes one attempt. The project's Feeds, spider Middleware, and Pipelines are left out, and the Run logs only critical records. `--timeout` must be positive. `describe_response()` and `is_text()` moved to `pernix.cli.fetch_output` and `pernix.cli.page_reading`.
- `crawl()` of `pernix.testing` turns `network.public_only` off, so that tests reach a `LoopbackServer` whatever the project file says; `settings=` turns it back on.
- `concurrency` is the number of workers for the Requests that do not render; rendered Requests have `browser.max_pages` workers more, so a Run processes up to `concurrency + browser.max_pages` Requests at once. `crawl(browser=...)` registers the `browser.*` settings, so `browser.max_pages` applies with a stand-in browser too.
- curl-cffi is pinned to 0.16.3, as patchright is, so that the HTTP Fetcher's Profile changes only with an upgrade that passes the Profile contract tests on macOS and Linux (ADR 0010). They show that, under one Session, the HTTP Fetcher and the browser put one client on the wire: the same TLS ClientHello, a resumed one included, HTTP/2 preface, HPACK representations, and header order; the values of `User-Agent`, `sec-ch-ua`, `sec-ch-ua-platform`, and `Accept-Language` are not compared yet.
- The HTTP Fetcher follows redirects itself, as browsers do, one transfer per hop. Only 301, 302, 303, 307, and 308 with a `Location` redirect, resolved as WHATWG URLs resolve it; 301 and 302 turn a POST into a GET, and 303 anything but GET and HEAD, without the body and the headers that describe it; `Authorization` and `Proxy-Authorization` never follow a redirect to another origin, another scheme, host, or port; a `Location` that is not a valid http or https URL fails the fetch with a `FetchError`, which is not retried. Each hop passes the network guard before it is sent, waits `http.timeout` for its headers, and uses the HTTP version of its scheme, so a redirect from `http://` to `https://` gets HTTP/2. `stream()` streams the last body only, the body of a redirect counts toward no byte limit, and `TooManyRedirects` has `code` 0.
- A `Cookie` header in a Request's headers is sent as its cookies, as `cookies=` are and as the browser Fetcher already did: to each redirect hop on its host, whatever its port or scheme, joined by the cookies set on the way.
- `Secret` moved to `pernix.secret`; `pernix.settings` still exports it. `sessions.cooldown` also cools a Session down after a failed login.
- `FetcherDispatch` passes the Session a Request is sent under to its Fetcher as `session=`, inside `pernix.fetchers.fetcher_dispatch.sending_as()`; a Fetcher without that parameter refuses such a Request. `Throttle.observe()` takes the statuses that pause the slot.
- `parse_set_cookie()` also reads `Domain`, `Path`, `Secure`, `HttpOnly`, and `SameSite` into `SetCookie`. `is_loopback_host()` moved to `pernix.urls`; `pernix.fetchers.network_guard` still exports it.
- `SpiderClosed.reason` and the `run.reason` stat gain `drained` and `forced`.
- An error that ends a Run is logged before it is raised, with its traceback unless it is a configuration error.
- A string that is not valid JSON for a container setting is reported as `invalid JSON`.
- From Python 3.14 on, the annotations of component and Spider `__init__` methods may name types defined later or imported only for type checking.
- The per-Request processing of the Engine moved to `pernix.request_processor.RequestProcessor`.
- Building and wiring the components of a Run moved from the Crawler to `pernix.run_assembly.RunAssembly`.

- `output=` writes jsonl, csv, or json by the file extension, as a Feed; other extensions are rejected. `pernix.feeds.JsonLinesFeed` is replaced by `Feed`.
- `ItemScraped` is emitted once an Item passed every Pipeline and was written to the Feeds, apart from its Callback. In Feed output, sets become lists, `Decimal`s strings, and values JSON cannot represent, such as `bytes`, fail the Run with `FeedError`.
- The Engine takes `put_item(item, ctx)`, an awaitable handoff, instead of `item_sink`.

- `StatsSnapshot` gains `final`, true for the snapshot taken at the end of a Run.
- During a Run, the `pernix` logger does not propagate: its records reach the root handlers from the writer thread, with the message already formatted and the exception rendered in `exc_text` instead of `exc_info`.
- A Spider object can belong to one Crawler only.

- `Extension` moved to `pernix.extensions`, next to the built-in Extensions; `from pernix import Extension` is unchanged.
- `RequestFailed` is emitted once per Request that fails for good, not once per failed attempt; the Item Events have `response=None` for Items an errback yields.
- The `Fetcher` protocol is `async def fetch(request)` plus `schemes`; Fetchers are opened and closed like other components and no longer check `render` or `fetcher` themselves.
- Requests are independent: cookies no longer persist from one Request to another. Pass `cookies=` explicitly, or use a Session Pool once available (ADR 0011).
- `Spider.run()` and `Spider.crawl()` take `settings={"concurrency": ...}` instead of a `concurrency` argument.
- `Request` refuses cookies that a `Cookie` header cannot carry as given: an empty name, a name with `=`, `;`, or a control character, or a value with `;` or a control character. The error names the cookie, never its value.

### Fixed

- `LoopbackServer` no longer prints a traceback when a client, such as a browser, drops a connection it kept open, which landed in the stderr of the tests.
- The HTTP Fetcher sends cookies in the order Chrome sends them: longer paths first, then the earliest set first, a cookie that replaces another keeping its place. curl ordered them by path, domain, and name length instead, the Request's own, a Session's, and those set on redirects alike.
- Cookies set over HTTP with values beyond ASCII in UTF-8 are kept in a Session as text, and sent back byte for byte; they were kept as Latin-1 and sent back garbled.
- The HTTP Fetcher reaches the host a browser does for international host names, on every platform. curl converted them to ASCII itself, and on Linux reached other hosts for some, such as `strasse.de` for `STRAẞE.de`, where `Request(cookies=...)` then never went. A host that is not ASCII, or holds percent escapes, is now converted as WHATWG URLs convert hosts before curl sees the URL, and `Response.url` names it in ASCII; a host WHATWG URLs reject fails the fetch with a `FetchError`, as browsers refuse such a URL. The network guard reads hosts the same way, so `localhost` in full-width letters, or as `local%68ost`, is a loopback host. `pernix.urls.url_host()` and `with_ascii_host()` give the host and the URL as the Fetcher uses them.
- Log redaction masks the user and password of a proxy given without a scheme, as curl takes it: `alice:pa55@proxy:8080` becomes `***@proxy:8080`, in messages, exception texts, and stats alike. Without a scheme, only a user and a password joined by a colon before `@` and a host are masked, so e-mail addresses are kept, `mailto:` ones included; either may be empty, and whatever is joined to them is masked too, as `proxy=` in `proxy=alice:pa55@proxy`. Every rule looks at the text as given, and again with secret values starred out, and values that several rules find, overlapping or side by side, are masked as one, so masking one value never hides another; a header name or quoted name is never taken for a user.
- The HTTP Fetcher sends `Request(cookies=...)` to hosts without a dot, such as `localhost`, `intranet`, or `[::1]`, which never received them. They are held for the Request's host only, for every path, so they go to each redirect hop on that host, whatever its port or scheme, and to no other host, in one `Cookie` header over HTTP/1.1 and a `cookie` field each over HTTP/2. Cookies named with the `__Secure-` or `__Host-` prefix, which were never sent, go over HTTPS, and to loopback hosts.
